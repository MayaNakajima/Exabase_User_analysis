# 仕様書 — エクサベースAI 利用実態分析

最終更新: 2026-08 ／ 対象データ: **2024-10-01〜2026-07-31（全22ヶ月）が現行**（全期間・月次版）

> 本仕様書は2部構成です。§1〜§7は初回の**単月版（2026年7月）**、末尾の**§A〜§G が現行の全期間・月次版**の追補仕様です。
> 運用・体制は `docs/運用手順書.md`、変更履歴とレビュー観点は `docs/変更履歴.md`、Git運用は `docs/引き継ぎ書.md` を参照。

## 1. 目的

社内AIツール「エクサベースAI」の利用ログから、以下を把握する。

1. AI利用による業務の再構築・効率化に向けた**社内サポートの示唆**を得る。
2. **リテラシーとチャットパートナー（モデル）選択の相関**を明らかにする。
3. **どの業務内容の利用が多いか**を把握する。
4. **業務内容とモデル階層の適切さ**を評価する（Standard/Premiumは従量課金のため、本当に必要な時のみ利用したい）。

## 2. 入力データ

エクサベースAI管理画面からの月次エクスポート `gai-export-*.xlsx`。1行=1メッセージ。

| 列 | 内容 |
|---|---|
| チャットパートナー | モデル名 + 階層 + 説明（例: `Gemini 2.5 Pro … / Standard/…`） |
| 会話ID | 会話（スレッド）単位のID |
| ユーザー | 社員メールアドレス |
| メッセージの時間 | タイムスタンプ |
| 役 | `user` / `assistant` |
| メッセージ | 本文 |
| 添付ファイル / 評価 / 利用ツール | 付随情報（利用ツールは `, ` 区切りで複数の場合あり。ただしツール名自体が括弧内にカンマを含むため、`10_ingest.py: split_tools()` が括弧の外のカンマだけで分割する） |

## 3. 集計単位と主要指標

### 3.1 会話単位（STEP1）
会話IDごとに、パートナー・モデル階層・往復数（user発話数）・使用ツール・
初回ユーザー発話・タイムスタンプを集約。

### 3.2 モデル階層
チャットパートナー文字列から `Economy` / `Standard` / `Premium` を抽出。
Standard・Premium は**従量課金**。

### 3.3 チャット内容 12分類（STEP2–3）
各会話の初回ユーザー発話を**AIが読んで**以下の12カテゴリに分類（全会話）。

| コード | カテゴリ |
|---|---|
| C01 | メール作成・返信・添削 |
| C02 | 文章校正・言い換え・敬語 |
| C03 | 資料・企画書・スライド作成 |
| C04 | 報告書・議事録作成 |
| C05 | 営業戦略・企業リサーチ・ABM分析 |
| C06 | 製品・素材・技術の相談 |
| C07 | 画像生成・画像編集 |
| C08 | 要約・翻訳・文書処理 |
| C09 | データ・Excel・表・計算 |
| C10 | IT・ツール操作サポート |
| C11 | アイデア出し・ネーミング・コピー |
| C12 | 業務知識・一般調査・その他 |

分類プロンプトは `scripts/classification_prompt.md`。

### 3.4 リテラシー複合スコア（STEP4）
ユーザーごとに次の6指標を算出し、**各指標を全ユーザー内の百分位（0-100）に変換**、
重み付き平均で 0-100 のスコアを得る。

| 指標 | 意味 | 重み |
|---|---|---|
| 平均往復数 | 会話の深さ（1会話あたりuser発話数） | 0.18 |
| 初回発話の平均文字数 | プロンプトの具体性 | 0.18 |
| 高度ツール活用率 | Deep Research/RAG/ファイル出力等を使う会話の割合 | 0.20 |
| 利用カテゴリ数 | 用途の多様性 | 0.16 |
| 構造化プロンプト率 | 役割設定・箇条書き・条件提示を含む会話の割合 | 0.18 |
| 利用ツール種類数 | 使いこなしているツールの幅 | 0.10 |

- 「高度ツール」の定義は `config.py: ADV_TOOLS`（13種・唯一の定義元。14/15 が import）。**画像生成(高速/高性能)は高度ツールから除外**（2026-08。件数が多く"深い使い方"の signal として弱いため。将来チャット内容に応じ高度分類する余地あり）。詳細は `docs/評価仕様.md §4`。
- 「構造化プロンプト」の判定は `04_analyze.py: is_structured()`（`あなたは〜専門家`等の役割設定、箇条書き・番号・記号、120字超で条件/背景/目的等のキーワードを含む）。

### 3.5 利用頻度
月内の**ユーザー発話数**（user役メッセージ数）。

### 3.6 4象限
利用頻度・リテラシーそれぞれの**中央値**で高/低を分割（本データでは頻度26 / スコア62.5）。

| 象限 | 定義 | 位置づけ |
|---|---|---|
| Q1 | 高頻度・高リテラシー | 横展開の担い手 |
| Q2 | 高頻度・低リテラシー | 量は使うが質に課題（研修効果大） |
| Q3 | 低頻度・高リテラシー | 使えるが機会が少ない |
| Q4 | 低頻度・低リテラシー | 未活用層／シャドウAIリスク |

### 3.7 過剰スペック候補（従量課金の適正性）
次を**すべて**満たす会話を「Economyで代替可能な過剰スペック候補」とする。

- モデル階層が Standard または Premium
- カテゴリが単純用途（C01 / C02 / C11 / C12）
- 往復が2回以下（`OVERSPEC_MAX_TURNS`）
- 高度ツール未使用

## 4. 相関分析
ユーザー単位で以下のピアソン相関を算出（`04_analyze.py`）。

- 利用頻度 × リテラシー
- リテラシー × Std/Prem発話比率（＝スペック選択が習熟度で説明できるか）
- リテラシー × 高度ツール活用率
- リテラシー × 平均往復数

## 5. 出力

### 5.1 Excel集計ブック `output/エクサベースAI_利用分析_202607.xlsx`
シート構成:

1. **サマリー** … 全体数値・主要インサイト・分析手法注記
2. **ユーザー別** … 全ユーザーの頻度/会話/スコア/象限/各指標/最多用途（オートフィルタ付）
3. **チャットパートナー別** … パートナー×階層の会話数・メッセージ数
4. **利用ツール別** … ツール別の利用会話数
5. **チャット内容分類別** … カテゴリ別会話数・構成比・階層内訳
6. **4象限サマリー** … 象限別の人数・指標・推奨アクション
7. **過剰スペック候補** … 該当会話の一覧（ユーザー・モデル・用途・抜粋）

### 5.2 ダッシュボード `output/エクサベースAI_利用分析_ダッシュボード.html`
単一HTML（Chart.jsをCDN読込）。KPIカード、4象限バブルチャート、相関サマリー、
カテゴリ別/階層別/パートナー別/ツール別グラフ、リテラシー×従量課金の散布図、
象限フィルタ・列ソート可能なユーザー別テーブル、示唆。

## 6. 主要な分析結果（2026年7月）

- 利用は二極化。**Q1(69名)が全会話の約78%**を占有。**Q4(67名)は1割未満**でシャドウAIが隠れる可能性。
- **リテラシーは利用頻度と相関（r=0.60）**する一方、**Std/Prem選択とはほぼ無相関（r=0.08）**。
  上位モデルは"必要性"ではなく習熟度と無関係に選ばれている。
- 高度ツール活用率は**Q1でも約5%**にとどまり、高付加価値機能の伸びしろが大きい。
- 従量課金404会話のうち**81件（20%）が過剰スペック候補**。
- 用途はメール16% / 画像編集15% / 一般質問12% / 営業リサーチ10% が中心。

## 7. 限界・留意点

- 分類は**初回ユーザー発話**を主判断材料とする（会話全体は見ていない）。多目的な会話は主目的で1カテゴリに割当。
- AI分類には僅かなばらつきがあり得る。境界ケースの規則は `classification_prompt.md` に明記。
- リテラシースコアは相対評価（母集団内百分位）。母集団が変われば絶対値は不変でも順位は変動する。
- 「過剰スペック」は機械的定義による**候補**であり、内容次第で妥当な利用も含まれ得る。最終判断は目視推奨。
- Premiumはサンプルが極小（8メッセージ）のため階層別の統計的比較には向かない。

# 【全期間・月次版】追補仕様（2024-10〜2026-07）

単月版を全期間・月次に拡張し、メンバー一覧（グループ・在籍）とClaude併用者を統合した。
現行の主分析はこちら（スクリプト 10〜17 / 成果物 `..._全期間.xlsx` `..._ダッシュボード_全期間.html`）。

## A. 入力の追加
- 月次エクスポート **複数ファイル**（エクスポートは3万行上限で分割。全パートを揃える）。会話は初回タイムスタンプの月(YYYY-MM)に割当。重複はメッセージキー(会話ID+時間+役+本文先頭)で排除。
- **メンバー一覧**（email/氏名/is_active/group_permission/subgroup_assignments/created_at/last_logged_in_at）。サブグループ権限トークンから**コア/ライト/ユーザー**を判定。利用実績はあるがメンバー表に無い利用者は**退職/不明**。

## B. 公平性（利用期間によらない比較）
利用頻度を **「稼働月あたりのユーザー発話数」= 総発話数 ÷ 稼働月数** で正規化。入退社・利用開始時期の差を排除する。4象限はこの正規化頻度とリテラシーの中央値で分割。リテラシーの各指標（往復・具体性・高度ツール率・多様性・構造化・ツール種類）は比率/平均のため元来テナー中立。

## C. グループ × 4象限
管理グループ（コア/ライト/ユーザー）と行動実態（Q1〜Q4）のクロスを算出。対角に近いほど整合、オフ対角が施策対象（例：ライト×Q4=定着支援、ユーザー×Q1=コア候補）。

## D. Claude併用者
`config.CLAUDE_USERS` の4名は高度用途をClaude（Claude Code含む）にオフロードするため、
ExaBaseの上位モデル利用・リテラシー解釈に注記し、**過剰スペック候補の集計から除外**。

## E. 成果物（全期間版）
- Excel: サマリー／月次推移／月次×グループ／**月次_用途別／月次_パートナー別／月次_ツール別**（各:データ表＋積み上げ縦棒グラフ）／ユーザー別_全期間／グループ×4象限／4象限サマリー／チャットパートナー別／利用ツール別／チャット内容分類別／Claude併用者／過剰スペック候補（14シート）。ユーザー別・Claude併用者シートの氏名は社員一覧マスタ（§H）で突合表示。
- ダッシュボード: KPI・導入推移（アクティブ/累計/新規）・月次量・階層推移・高度ツール/過剰スペック推移・4象限バブル（グループ色・Claude◆）・グループ×象限・グループ別月次アクティブ・用途/パートナー（全期間）＋**用途・チャットパートナー・ツールの月次推移（スタック棒／実数⇔構成比％切替）**・フィルタ付ユーザー表・グループ別示唆。加えて §H の「氏名表示・検索・示唆キャプション・リテラシー向上ガイド」を搭載。

## H. 氏名突合・ダッシュボードの示唆表示（現行）

**目的**：分析の意味（示唆）を各グラフに併記し、リテラシー向上の観測点を直感的にし、氏名で人を特定・検索できるようにする。

### H.1 社員一覧マスタ（氏名突合）— STEP18
- 入力：人事の社員一覧CSV `data/raw_exports/社員一覧*.csv`（Shift-JIS/cp932）。複数可。
- `18_employee_master.py` が**メールアドレスをキー**に `data/employee_master.json`（氏名・カナ・部署・役職・在籍）を生成。
- 列は**ヘッダー名で動的マッピング**（年により列位置がずれても追従）。**新しい年を優先**し、古い年で退職者等を補完。
- 部署＝「組織グループ＋Div.＋部＋課」を連結。**管理グループ（コア/ライト/ユーザー）はエクサベース権限由来**であり本マスタでは扱わない（氏名等の表示情報のみ供給）。
- 突合率は利用293名中286名（97.6%）。未突合はメール表示でフォールバック。16/17がメール突合して利用。

### H.2 グラフごとの「見方・示唆」
全チャート下に、①軸/凡例の**見方**と②そこから読む**示唆**を併記（過剰スペック比率・アクティブ増減などデータ由来の動的数値入り）。

### H.3 リテラシー向上ガイド（観測点の明示）
KPI直下に常設。リテラシー複合スコアの**6指標（重み付き）**と、**観測すべきグラフ**を明示する。
- 最重要レバー＝**高度ツール活用率の推移**（全社で数%と低く伸びしろ最大）。
- 個人の状態＝**4象限の縦軸（リテラシー）**、右上Q1への移動が育成ゴール。
- 個人の弱点＝**ユーザー表のリテラシー列にホバー**すると6サブ指標（往復・具体性・高度ツール%・用途多様性・構造化%・ツール種類）＋手戻り率・テンプレ率の内訳を表示。
- **「評価方法の概要と限界」パネル**（折りたたみ）で評価の考え方・バイアス補正・限界を明示。

### H.5 評価バイアス補正（現行反映済み）
往復の単純カウントや初回文字数・構造化には次のバイアスがあるため補正する（詳細は `docs/評価仕様.md`）。
- **手戻り除外**：AI失敗由来の「やり直し／回答が違う／エラー」等の再依頼を検出し、会話の深さ（往復）から差引（`config.REWORK_PAT`）。手戻りは"深い使い方"に加点しない。
- **テンプレ/エージェント由来の除外**：同一の初回発話を複数人（`TEMPLATE_MIN_USERS`人以上）が共有する場合、定型文とみなし**具体性(文字数)・構造化率の加点対象から除外**（本人の作文力のみ評価）。エージェントでAI発話から始まる場合は元々「初回ユーザー発話」を採用。
- 反映規模（本データ）：テンプレ89種／テンプレ由来会話4.0%／手戻り発話4.8%。

> **算式・判定条件・限界の詳細は [`docs/評価仕様.md`](評価仕様.md) を参照**（リテラシーの計算式、手戻り検出語、テンプレ閾値、高度ツール定義、過剰スペック条件、7月データ破損の注記等）。

### H.4 ユーザー検索
ユーザー別明細に検索ボックスを追加。**氏名・カナ・メール・部署・役職**を横断してインクリメンタル検索（一致箇所をハイライト）。既存のグループ/象限/Claude/在籍/過剰フィルタ・並び替えと併用可。CSV出力にも氏名・カナ・部署・役職・6サブ指標を含める。

## F. 主要結果（全期間）
- 導入拡大：月次アクティブ 36→163名、月次会話 230→2,521件、累計利用者 293名。
- グループと4象限は概ね整合。Q1比率：コア 11/13 ＞ ライト 65/113 ＞ ユーザー 22/143。
- オフ対角：ライト×Q4 18名（定着支援）、ユーザー×Q1 22名（コア候補）。
- リテラシー×Std/Prem選択は無相関(r≈0.10)、リテラシー×稼働月頻度は r≈0.47。
- 過剰スペック候補（Claude4名除く）は全期間 3,167件。

## G. データ保持
`data/raw_exports/`（原本xlsx=正本）＋ `data/archive/messages_YYYY-MM.jsonl.gz`（重複排除・全文・月別gzipの正規化マスタ、`build_archive.py`で生成・追記）。両者とも `data/` 配下でGit対象外。

### G.1 処理済みスナップショット（引き継ぎ・再生成用）— STEP19
生データ（月次エクスポート20+ファイル＋社員CSV）を集め直さなくても成果物（16 Excel / 17 ダッシュボード）を再生成できるよう、ビルド工程が読み込む**処理済み中間データ一式**（`aggregates_all.json`／`user_all.json`／`meta_all.json`／`employee_master.json`＝合計約0.6MB）を年月付きスナップショットとして保存する（`19_snapshot.py`）。
- 保存: `19_snapshot.py [--zip]` → `data/snapshots/snapshot_<最新月>/`（`--zip`でBox共有用の単一zipも生成）。ラベルはデータの最新月基準。`manifest.json`（生成日時・各ファイルのSHA256）を同梱。
- 復元: `19_snapshot.py --restore <フォルダ/zip>` で `data/` に展開 → `16`→`17` を実行するだけで保存時点と同一の成果物を再生成（重い取込・分類は不要）。
- **PII**: 氏名・部署を含むため `data/snapshots/` はGit対象外。共有は `output/` と同様に**Box経由**（公開Gitには載せない）。用途/パートナー/ツール等の非PII集計値のみを共有したい場合は別途エクスポートを検討。
