# 評価仕様 — リテラシー・利用頻度・4象限・過剰スペックの算式と判定条件

最終更新: 2026-08 ／ 対象: 全期間・月次版（scripts 10〜18）

本書は各指標の**具体的な計算式・判定条件・バイアス補正・限界**を定義する詳細仕様。
概要と運用は `仕様書.md`（§3, §H）／`引き継ぎ書.md` を参照。ダッシュボードの「評価方法の概要と限界」パネルは本書の要約。

## 0. 集計単位

- **1メッセージ = 1行**（生エクスポート）。`10_ingest.py` が会話ID単位に集約し `conversations_all.json` を作る。
- 重複排除キー：`(会話ID, タイムスタンプ, 役, 本文先頭60字)`。
- 会話は初回タイムスタンプの月(YYYY-MM)に割当。
- 会話ごとに保持する値：`user_msgs`(user発話数)／`asst_msgs`(assistant発話数)／`rework_msgs`(手戻り発話数, §2)／`first_user_msg`(最初のユーザー発話, 400字上限)／`first_len`(その文字数)／`tools`(使用ツール集合)／`tier`(モデル階層)。

## 1. リテラシー複合スコア（0〜100）

### 1.1 6つの生指標（ユーザー単位）
`14_analyze.py` がユーザーごとに算出する。

| 指標 | 定義 | 重み |
|---|---|---|
| `avg_turns` 会話の深さ | **実質往復**の平均＝`max(1, user_msgs − rework_msgs)` を会話平均（§2で手戻り補正） | 0.18 |
| `avg_len` 具体性 | 初回ユーザー発話の文字数（400字上限）の平均。**テンプレ由来の発話は除外**（§3） | 0.18 |
| `adv_rate` 高度ツール活用率 | 高度ツール（§4）を使った会話数 ÷ 総会話数 | 0.20 |
| `cat_div` 用途の多様性 | 使った**異なるカテゴリ数**（12分類, §5） | 0.16 |
| `struct_rate` 構造化率 | 構造化された初回発話（§6）の会話数 ÷ 総会話数。**テンプレ由来は加点しない**（§3） | 0.18 |
| `distinct_tools` ツール種類数 | 使った異なるツールの数 | 0.10 |

### 1.2 百分位変換と加重平均
1. 各指標を、全利用者（293名）内の**百分位(0〜100)**に変換：
   `P(v) = (値がv以下の人数 ÷ N) × 100`（`bisect_right`。同値は「以下」に含む）。
2. 重み付き平均：

```
literacy = 0.18·P(avg_turns) + 0.18·P(avg_len) + 0.20·P(adv_rate)
         + 0.16·P(cat_div) + 0.18·P(struct_rate) + 0.10·P(distinct_tools)
```

3. 0〜100・小数1桁。**相対評価**（母集団内の順位）であり絶対スキル値ではない。母集団が変われば同じ使い方でも値は変動する。
4. 重みは `config.LITERACY_WEIGHTS`（合計1.0）で変更可能。

## 2. 会話の深さの手戻り補正（バイアス補正①）

**課題**：往復数の単純平均では、「指示がおかしかった／回答が希望と違った→やり直し」というAI失敗由来の**手戻り**も、建設的な深掘りと同じく往復増として加点されてしまう。

**対応**：`10_ingest.py` が各ユーザー発話を `config.REWORK_PAT`（正規表現）で判定し、手戻り発話数 `rework_msgs` を会話ごとに集計。深さは **`max(1, user_msgs − rework_msgs)`**（最低1往復は保証）。

- 検出語（例）：やり直し／もう一度／再度／作り直し／書き直し／違う／そうじゃない／ダメ／エラー／失敗／反映されない／できていない／表示されない／希望と／イメージと 等。全文は `config.REWORK_PAT`。
- **限界**：キーワードベースのため、正当な追加指示の一部を手戻りと誤判定しうる（往復は最低1を保証するため過小評価側に倒れる）。逆に語彙に無い手戻りは拾えない。
- ダッシュボードのユーザー表「リテラシー」列ホバーで**手戻り率**（rework_msgs ÷ 全発話）を参考表示。

## 3. テンプレ/エージェント由来の水増し補正（バイアス補正②）

**課題**：テンプレートやエージェントが初回のユーザー入力に長い定型文・構造化文面を流し込む場合、`avg_len`（具体性）や `struct_rate`（構造化率）が**本人の作文力ではないのに加点**されてしまう。

**対応**：`14_analyze.py` が全会話の初回発話を正規化（`config.norm_key`＝空白除去・先頭120字）し、**同一の正規化発話を `config.TEMPLATE_MIN_USERS`(=3) 人以上が共有**する場合、その発話を**テンプレ由来**とみなす。テンプレ由来の初回発話は：

- `avg_len`（具体性）の**集計から除外**（本人が書いた発話のみで平均）。全会話がテンプレのユーザーは avg_len=0。
- `struct_rate` の**分子に加点しない**（分母は全会話のまま）→ テンプレ多用者の構造化率は下がる。

- なお**エージェントがAI側発話で始まる**場合は、初回「ユーザー」発話を採用するため、AIの挨拶が具体性・構造化として誤カウントされることは元々ない（`10_ingest.py` の first_user_msg 抽出）。
- **限界**：「3人以上共有」は定型文検出の近似で、少人数だけが使う独自テンプレは検出できない。逆に偶然一致した短い定型句を巻き込む可能性がある（ただし短文は元々スコアへの寄与が小さい）。
- ダッシュボードのホバーで**テンプレ率**（テンプレ会話 ÷ 総会話）を参考表示。

## 4. 高度ツールの切り分け基準

- `config.ADV_TOOLS`（**13種**・唯一の定義元）の**手動キュレーション許可リスト**。会話がこの集合のツールを**1つでも**使えば「高度ツール利用会話」。14/15 は本 config を import して使う（インライン重複は廃止）。
- 収録：Deep Research (詳細)／文書検索 (RAG)／スライド作成 (PowerPoint)／ファイル出力 (Word、Excelなど)／ウェブリサーチ (高速)／国内記事検索／官公需案件検索／音声書き起こし／SharePointファイル検索／Teams検索／Outlookカレンダー予定確認／Box検索／ヘルプページ検索。
- **画像生成の扱い（2026-08〜）**：`画像生成 (高速, Nano Banana)`／`画像生成 (高性能, GPT-image)` は**高度ツールから除外**。件数が多く、また「準備・前処理を要する深い使い方」の signal としては弱いため。**将来、チャット内容（詳細な指示・反復調整・成果物への組込み等）に応じて高度に分類する改修余地あり**（その場合は条件付きで戻す/別指標化）。
- 基準の考え方：単なるチャットより**準備・前処理を要し、外部データ参照や成果物出力など高付加価値**を生む機能。使った“事実”を見るもので、使い方の巧拙は測っていない。
- **限界**：定性判断のリストであり、**新ツール追加時は `ADV_TOOLS` の更新が必要**（漏れると過小評価）。
- **ツール列のパース（重要）**：エクスポートの「利用ツール」列は複数ツールを `, `（ASCIIカンマ）で連結するが、
  ツール名自体が括弧内にカンマを含む（`画像生成 (高速, Nano Banana)`／`ファイル出力 (Word、Excelなど)` 等）。
  素朴な `split(",")` はこれらを誤分割し、集計・`ADV_TOOLS`一致・**ツール種類数**を誤らせる。
  現行は `10_ingest.py: split_tools()` が**括弧の外のカンマだけで分割**して正しく復元する（2026-08修正）。

「本分析で言う"高度な利用"」＝この高度ツール活用率を指す（別の総合フラグは持たない）。

## 5. 用途の多様性（12分類）

- 各会話の**初回ユーザー発話をAIが読み**、主目的で C01〜C12 の1カテゴリに割当（`classification_prompt.md`。ツールは補助情報）。
- 多様性 `cat_div` ＝そのユーザーが使った**異なるカテゴリ数**。
- 12分類：C01メール／C02校正・敬語／C03資料・スライド／C04報告書・議事録／C05営業リサーチ・ABM／C06製品・技術／C07画像／C08要約・翻訳／C09データ・Excel／C10IT操作／C11アイデア・ネーミング／C12一般調査・その他。
- **限界**：初回発話のみで判定（多目的会話は主目的1つに割当）。AI分類には僅かなばらつき。境界規則は `classification_prompt.md`。

## 6. 構造化プロンプトの判定

`14_analyze.py: is_structured(初回発話)` が次のいずれかで True：
- 役割設定：`あなたは〜(専門家|プロ|コピーライター|リサーチャー|コンサル|担当)`。
- 箇条書き・番号・記号行：行頭の `1. / 1) / ・ / - / * / # / 【`。
- 120字超で `(条件|前提|背景|目的|制約|フォーマット|以下の|＃|#)` を含む。

§3のテンプレ由来はここで加点しない。

## 7. 利用頻度と4象限

- **利用頻度**＝`msgs_per_month`＝総ユーザー発話数 ÷ **稼働月数**（発話のあった月数）。入退社・利用開始時期の差を排除する公平化。
- **4象限**：利用頻度・リテラシーそれぞれの**中央値**で高/低に分割（本データ：頻度中央値 12.5 ／ リテラシー中央値 60.3 付近。再実行で変動）。

| 象限 | 定義 | 位置づけ |
|---|---|---|
| Q1 | 高頻度・高リテラシー | 横展開の担い手 |
| Q2 | 高頻度・低リテラシー | 量は使うが質に課題（研修効果大） |
| Q3 | 低頻度・高リテラシー | 使えるが機会が少ない |
| Q4 | 低頻度・低リテラシー | 未活用／シャドウAIリスク |

- 管理グループ（コア/ライト/ユーザー）×4象限のクロスで、権限と実態のズレ（例：ライト×Q4＝定着支援、ユーザー×Q1＝コア候補）を抽出。

## 8. 過剰スペック候補

会話が**次を全て満たす**とき1件（`config.SIMPLE_CATS` / `OVERSPEC_MAX_TURNS` / `CLAUDE_USERS`）：

1. モデル階層が **Standard または Premium**（従量課金）
2. カテゴリが**単純用途** C01/C02/C11/C12
3. **往復2回以下**（`OVERSPEC_MAX_TURNS = 2`。ここは補正前の生 `user_msgs`）
4. **高度ツール未使用**
5. **Claude併用者（4名）は除外**

意味＝「Economyで代替できたはずの上位モデル利用」。あくまで機械的**候補**であり、最終判断は内容の目視推奨。

## 10. 全体の限界（まとめ）

- 分類・テンプレ判定・構造化・具体性は**初回ユーザー発話**が主材料（会話全体は見ていない）。
- 手戻り検出・テンプレ検出はヒューリスティックで、誤判定が一定量ありうる（設計上は過小評価側）。
- リテラシーは**相対評価**（母集団内百分位）。
- 高度ツールは手動リスト運用。
- 過剰スペックは機械的**候補**。Premiumはサンプル極小で階層別統計比較には不向き。

> 補足（2026-08 解決済み）：一時 `gai-export-2026_07_01-2026_07_31.xlsx` が破損し7月の手戻り補正が未適用だったが、**正常ファイルを再取得して全期間を再取り込み済み**。7月の手戻りも反映されている（全期間の手戻り発話 5,623件）。
