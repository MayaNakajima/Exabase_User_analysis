# 運用手順書 — エクサベースAI 利用分析ダッシュボード（複数人運用）

最終更新: 2026-08 ／ 対象: 月次更新・共有・閲覧の定常運用

## 0. 前提・方針（合意事項）

- **閲覧範囲**: 関係者は**全員実名**で閲覧（社員名＝メールのローカル部を表示）。匿名化版は作らない。
  そのぶん **社内限定** を徹底する（後述のセキュリティ）。
- **体制**: 月次更新は **主担当＋副担当の2名体制**（属人化を防ぐ）。
- **共有**: 成果物・データは **Box の実行用フォルダ** で共有（`生成AI/DX推進課/…/Exabase_User_analysis`）。
- **STEP3（AI分類）**: **差分運用**（新規会話のプロンプトだけAI分類。過去分は `classification_store.json` を再利用）。
- **コード**: GitHub（Private）。作業はブランチ→レビュー→mainマージ。コミットはGitHubアプリ。

## 1. 体制と役割

| 役割 | 担当 | 責務 |
|---|---|---|
| 主担当 | （記入） | 月次エクスポート取得・パイプライン実行・STEP3分類・成果物のBox反映 |
| 副担当 | （記入） | 数値レビュー・欠測チェック・主担当不在時の代行 |
| レビュー承認 | （記入） | 施策への反映可否の最終確認 |
| 閲覧者 | 関係部署 | ダッシュボード/Excelの閲覧・フィルタ活用（更新不可） |

RACI（月次更新）: 実行=主担当 / 確認=副担当 / 承認=レビュー承認 / 共有=主担当。

## 2. 月次運用フロー（目安：30〜60分）

1. **データ取得**（主担当）
   - エクサベース管理画面から対象月を含むエクスポート（`gai-export-*.xlsx`、3万行で分割されるため**全パート**）と
     最新のメンバー一覧（`gai-members-export-*.xlsx`）を取得。
   - Box → `00_data`（`C:\Users\612316\Box\事業推進Div□\DX推進課\生成AI\00_data`）に配置（原本はBoxで保持）。

2. **取込・整形**（主担当）
   ```bash
   cd scripts
   python 10_ingest.py     # 月次件数の連続性を確認（急減=パート欠落のサイン）
   python 11_members.py     # グループ/在籍/Claudeを更新
   ```

3. **STEP3 差分分類**（主担当）
   ```bash
   python 12_classify_prep.py   # 「新規=N件」を確認。Nが0なら分類作業は不要
   ```
   - 新規がある場合のみ、`data/chunks2/c*.json` を Cowork のサブエージェント等でAI分類し
     `r*.json` を保存（プロンプトは `scripts/classification_prompt.md`）。差分なので通常は少量。
   ```bash
   python 13_merge_classification.py   # store更新＆全会話へ再展開。フォールバック(C12)=0 を確認
   ```

4. **集計・生成**（主担当）
   ```bash
   python 14_analyze.py
   python 15_aggregate.py
   python 16_build_xlsx.py
   python 17_build_dashboard.py
   ```

5. **保持アーカイブ更新＋処理済みスナップショット**（主担当・任意）
   ```bash
   python build_archive.py       # data/archive/ に月別gzipを追記
   python 19_snapshot.py --zip   # data/snapshots/ に成果物の再生成に必要な中間データ一式を保存＋Box共有用zip
   ```
   - スナップショットは、生データを集め直さず `16`/`17` を再生成するための引き継ぎ用（詳細は仕様書 §G.1）。
     受領側は `python 19_snapshot.py --restore <zip>` → `16` → `17` だけで同一成果物を再生成できる。

6. **レビュー**（副担当）
   - `10_ingest` の月次推移に不連続が無いか（＝欠測の検知）。
   - `13` のフォールバックが0、`14` の象限合計=利用者数、`15` の各合計=総会話数。
   - ダッシュボードをブラウザで開き、①〜⑥すべて表示されるか（`DATA_PLACEHOLDER` 残存なし）。

7. **共有**（主担当）
   - `output/` の Excel・ダッシュボードHTML を Box にアップロード（ファイル名に年月を付す：後述）。
   - 閲覧者へ更新を周知。

## 3. STEP3 差分分類の仕組み（コスト削減）

- 分類は「初回発話の正規化キー→カテゴリ」を `data/classification_store.json` に**蓄積**する。
- 毎月 `10_ingest` は全履歴を再取込するが、`12_classify_prep` は**storeに無い新規キーだけ**を
  チャンク化する。テンプレ再利用が多い実運用では、月次の分類対象は大きく減る。
- 新規キーが0件の月は分類作業そのものが不要（`13` を実行すればstoreから再展開）。
- storeは `data/` 配下（Git対象外）。Boxで主・副が同じstoreを共有すると差分が効く
  （storeが無い環境では初回だけ全件分類になる点に注意）。

## 4. 共有・命名規則（Box）

- 置き場: Box 実行用フォルダ。`output/`（Excel・HTML）と `data/raw_exports/`（原本）を格納。
  引き継ぎ用に `data/snapshots/exabase_processed_<年月>.zip`（19_snapshot の処理済み中間データ）も置くとよい。
- 命名: 月次の成果物ファイルは年月を付けて履歴を残す。例
  `エクサベースAI_利用分析_ダッシュボード_2026-08.html` / `…_全期間_2026-08.xlsx`。
  （スクリプトは固定名で出力するため、Boxアップロード時にリネーム。または16/17の出力名に年月を付す改修も可）
  ※「処理済みスナップショット」（19_snapshot が作る中間データzip）とは別物。前者は閲覧用の成果物、後者は再生成用の入力。
- 閲覧: ダッシュボードHTMLはダウンロードしてブラウザで開く（Chart.jsをCDN取得するため要ネット接続）。

## 5. セキュリティ（実名運用のため厳守）

- リポジトリ（GitHub）・Boxフォルダは **Private / 社内限定** を必ず維持。外部共有リンクは発行しない。
- `data/` と `output/` は Git 管理対象外（`.gitignore`）。個人情報・チャット本文/抜粋を含む。
- ダッシュボード/Excelは社内の関係者のみに配布。転送・外部保存は禁止。
- 退職者の扱い: メンバー表に無い利用者は「退職/不明」として集計に残る（過去実績の連続性のため）。
  氏名の取り扱いは社内規定に従う。

## 6. Git／ブランチ運用

- 作業ごとにブランチを切る（例 `feature/...`, `fix/...`）。`docs/変更履歴.md` に作業内容を記録。
- コミット・マージは GitHub アプリ、または `tools/` のバッチで実施。レビュー後 main へ。
  - 初回のみ: `tools\git-init-main.bat "初回コミット: 分析基盤一式"`
  - 通常: `tools\git-commit-branch.bat feature/xxx "説明"` → レビュー → `tools\git-merge-to-main.bat feature/xxx`
- コード（scripts/docs/tools/README）のみ追跡。データ・成果物は追跡しない。
- 注意: Cowork等の別環境から `.git` へ git 操作を行わない（別ユーザー権限のファイルが残り不整合の原因）。

## 7. トラブル時

- **ある月だけ件数が急減**: エクスポートのパート欠落。全パートが揃っているか確認し `10_ingest` を再実行。
- **`13` でフォールバック(C12)が増える**: 新規キーの分類漏れ。`12` の新規件数と `r*.json` の件数を突合。
- **ダッシュボードの一部セクションが出ない**: ブラウザのConsole(F12)でエラーを確認。
  グラフ追加時は各 `new Chart` に `type` 指定を忘れない（過去の不具合例）。
- **GitHub Desktopでコミット不可**: `.git/index.lock` の残存を疑い削除。改善しなければ
  `.git` を作り直す（コミットが無ければ安全）。**Cowork等の別環境からgitコマンドを実行しない**
  （`.git` に別ユーザー権限のファイルが残り不整合の原因になる）。
